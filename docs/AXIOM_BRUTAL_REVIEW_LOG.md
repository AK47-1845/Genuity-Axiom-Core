# Axiom Brutal Review Log

## Core assumption

Industrial AI teams will pay to close costly rare-scenario and data-access gaps when the generated artifact is integrated into a real validation workflow and supported by evidence accepted by engineering, privacy and security owners.

This assumption is plausible but not yet proven by repository depth, programs, grants or unpaid POCs. It becomes true only through paid repeat usage and measurable downstream results.

## Fatal flaws found and resolved in v0.3

1. Composite quality could hide a privacy or physical-validity failure → independent hard gates.
2. Small data reused as its own holdout → independent-holdout blocker.
3. Missing privacy dependency reported perfect safety → NumPy evidence or unavailable/blocked.
4. Conditional request could silently become unconditional → fail-closed validation and 100% match gate.
5. Non-tabular data could receive tabular approval → modality-appropriate evidence blocker.
6. Compliance preprocessing was not a release check → explicit compliance blocker.
7. Numeric sensor values could look like phone numbers → type-aware pattern scanning.
8. Broad privacy keywords removed legitimate features → contextual column-name logic.
9. Warning constraints behaved like hard errors → error/review separation.
10. Rare-event novelty parameter was not enforced → actual normalized distance filter.
11. Manifests hashed but did not preserve configuration → JSON-safe configuration snapshot.
12. DP and human approvals were booleans → structured evidence records.
13. Releases never expired → drift, expiry, revalidation and revocation primitives.
14. External adapters had no data-boundary control → policy registry and versioned descriptors.
15. Review artifacts could be exported before approval → approved-only CLI export.
16. CLI could overwrite source/existing artifacts → collision and explicit overwrite controls.
17. Legacy aspirational API looked shipped → prominent legacy notices and executable capability registry.

## Remaining gaps a sophisticated buyer will challenge

### Product evidence

- no disclosed paid production customer or repeatable annual contract;
- no independently reproducible benchmark across multiple industrial customers;
- aerospace augmentation/TSTR claims still need a preserved experiment dossier;
- no proof yet that scenario packs reduce a customer’s validation cost or improve model safety enough to buy repeatedly.

### Technical depth

- local tabular models are conservative baselines, not category-leading neural synthesis;
- temporal baseline does not learn long-range dynamics or causal control response;
- relational baseline preserves integrity but not full cross-table dependence;
- no native visual/audio/video generator or modality-specific evaluator;
- no integrated physics solver or calibrated simulator;
- no formal-DP mechanism/accountant shipped;
- membership evidence is numeric-feature oriented and does not replace a complete disclosure-risk study;
- no attribute-inference, linkage, fairness or expert de-identification suite;
- no distributed scale, GPU orchestration or production connectors.

### Enterprise platform

- no identity-backed control plane, SSO/RBAC, tenant isolation or signed approvals;
- no production VPC/on-prem runner, KMS integration or immutable audit service;
- no independently assessed security/certification posture;
- no job queue, artifact registry, approval UI, support/SLA or disaster recovery system;
- Python evidence objects are foundations, not a completed governed SaaS.

## Current verdict

**Strong direction and credible v0.3 validation foundation; not yet a million-dollar enterprise product.** It is ready for tightly scoped LTTS/design-partner pilots where outputs remain offline, domain owners review constraints, and Axiom’s evidence bundle is tested against a real holdout or calibrated simulator. It is not ready for claims of universal multimodal synthesis, anonymity, regulatory compliance, safety certification or production world models.

## What changes the verdict

1. One paid LTTS/client workflow with economic baseline and independent acceptance.
2. Replication on a second asset/configuration and one external design partner.
3. Private runner plus the connector/evaluator pulled by that workflow.
4. A case study showing decision metric and cycle-cost improvement, with claim ledger.
5. Conversion to a repeat/annual commitment.

Then Axiom can credibly move from “well-designed library and pilot system” to “repeatable industrial data product.” Enterprise valuation and contract size follow embedded value and trust—not code volume.

## Kill criteria

Narrow or change direction if four months produce no economic buyer, no independent validation truth, no downstream improvement, no repeated workflow, or no paid next step. Do not compensate by adding more generators, modalities or world-model language.
